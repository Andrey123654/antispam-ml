# Антиспам на основе решения хакатона

**Публикация проверена:** https://mkb251-razhnovap-antispam.onrender.com — работают форма, `/health` и `/predict`; публичные ответы совпали с локальной моделью. Бесплатный Render может засыпать при простое.

Ражнов Андрей, МКБ251. Итоговое задание по дисциплине «Применение ML в кибербезопасности».

Проект развивает авторскую работу [по фишинговым URL](https://github.com/Andrey123654/Hakaton).
Из неё перенесены автономные признаки ссылок и подход к OOF-стекингу.
Модель заново обучена на письмах: результат турнира по URL **не является метрикой антиспама**.
[Презентация](https://docs.google.com/presentation/d/1ZeNxPq8HVoR4I0T2b5IIu66GWBjEMd3Q1QUmaRmeyRs/edit). Исходный код: https://github.com/Andrey123654/antispam-ml .

## Что перенесено из хакатона

`src/vendor/hackathon_features.py` — точная копия `src/features.py` из Hakaton,
commit `afd2206d6d172b369b620d01ba10d6776219ad90`; SHA256 `a66ad4d77f82d1b0369cbda4fa094765b07ef2046b1e3ceacfb3b26ec64f3089`.
Адаптер `src/hackathon_adapter.py` извлекает 24 признака каждой ссылки:
структуру URL, IP вместо домена, userinfo, кодирование, мимикрию бренда,
тайпсквоттинг и слова-приманки. Для письма рассчитываются максимумы, средние,
число ссылок и признак усечения: всего 50 новых числовых признаков.
Обрабатываются первые 50 ссылок длиной до 2048 символов; счётчик учитывает все ссылки.

Итог: TF-IDF слов и символов + 94 признака письма + 50 признаков ссылок →
LR, SVM, ComplementNB и HistGradientBoosting → логистическая мета-модель.
Мета-модель обучается на OOF-предсказаниях базовых моделей, а не на их
предсказаниях по собственным обучающим строкам.

Веса фишинговой модели, метки турнира и снимки DNS/TLS/HTTP/RDAP не переносятся.
При проверке письма нет сетевых запросов к его ссылкам. В материалах хакатона
зафиксирован публичный F1 0,996062; он относится к другой задаче и другому тесту.
Прирост именно от блока ссылок отдельной абляцией пока не доказан.

## Данные и оценка

Исходный пул: 9055 писем — SpamAssassin, Ling-Spam и 25 синтетических
транзакционных примеров. После нормализации, дедупликации и удаления всех
совпадающих с тестом текстов осталось 7848.
Разбиение: 6278 development, 1570 validation,
1545 test; seed 42. Из пула удалены тексты, совпадающие с 1203
тестовыми письмами. Хеши и принадлежность к частям: `artifacts/hackathon_v2/split_manifest.csv`.
Точные пересечения между всеми тремя частями отсутствуют.

SpamBase скачан, его словарь использован при построении 57 признаков, но строки
SpamBase **не поступают в обучение** этой модели. Основных текстовых корпусов два.

5-фолдовая CV базовых моделей выполняется только на development; словари TF-IDF
и SVD обучаются внутри каждого фолда. Метрики CV лежат в `cv_base_models`.
Независимая вложенная CV всего стекинга не заявляется.
Порог **0.710376138877** выбран только по validation: максимум recall при
эмпирическом FPR ≤ 1 %. Валидация использована для настройки и не считается финальным тестом.

| Оценка | Писем | F1 | Precision | Recall | FP / нормальных |
|---|---:|---:|---:|---:|---:|
| Валидация для выбора порога | 1570 | 0.98204 | 0.97910 | 0.98498 | 7/1237 (0.57 %) |
| Весь локальный тест | 1545 | 0.93878 | 0.99184 | 0.89110 | 7/590 (1.19 %) |
| Исторически новый срез | 342 | 0.84342 | 0.97131 | 0.74528 | 7/24 (29.17 %) |

Все оценки теста получены **одной сохранённой моделью и одним порогом**.
Все 1545 текстов исключены из текущего обучения. Срез 342 — письма, которых не
было даже в исходном историческом пуле; он приведён для сопоставления с прошлой работой.
На нём всего 24 нормальных письма, поэтому 7 FP означают FPR 29,17 %.
На всём тесте FPR 1,19 % — ограничение валидации не гарантирует FPR ≤ 1 % на новой почте.

Локальный тест уже изучался в предыдущих итерациях. Близкие дубликаты и цепочки
переписки не группировались. Нужна новая внешняя проверка; результаты нельзя
трактовать как подтверждение качества на современной входящей почте.
Источник локального архива записан в `scripts/download_data.sh`; его соответствие
актуальной ссылке LMS отдельно не подтверждено.

## Категории писем

Сохранена отдельная модель: реклама, работа, знакомства, финансы, доставка,
безопасность и «прочее». Разметка получена правилами; качество в
`artifacts/category_metrics.json` характеризует воспроизведение слабой разметки,
а не согласие с экспертами. Модель категорий унаследована из v1 и не является
частью новой независимой оценки spam/ham.

## Запуск и воспроизведение

```bash
python -m venv .venv
.venv/bin/pip install -r service/requirements.txt
.venv/bin/python scripts/fetch_models.py artifacts
.venv/bin/uvicorn service.app:app --host 127.0.0.1 --port 8012
```

`GET /` — форма проверки; `GET /health` — состояние, вид модели и порог;
`POST /predict` и `POST /predict_batch` — классификация; `GET /docs` — контракт API.
По умолчанию порог берётся из артефакта. Переопределение `SPAM_THRESHOLD` явно
отмечается в `/health` и делает приведённые метрики неприменимыми к новому порогу.

```bash
# Обучение адаптации на подготовленных CSV (несколько минут на CPU)
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 .venv/bin/python -m src.adapt_hackathon
# Проверка сохранённой модели и API
.venv/bin/pip install -r requirements-dev.txt
OMP_NUM_THREADS=2 .venv/bin/python tools/verify_project.py
# Docker
 docker build -t antispam-hackathon:2 .
 docker run --rm -p 8012:8000 antispam-hackathon:2
```

Не запускайте старый `src/train.py` для воспроизведения v2: это исторический конвейер.

## Публикация

Модели вынесены в отдельный выпуск `v2.0-hackathon-email`; manifest содержит
контрольные суммы всех частей и собранных файлов. `scripts/fetch_models.py`
проверяет их перед использованием. `render.yaml` готовит Docker-сервис с `/health`.
Публичное демо: https://mkb251-razhnovap-antispam.onrender.com .
На бесплатном тарифе Render первый запрос после простоя может занять больше времени.
