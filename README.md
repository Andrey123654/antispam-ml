# Антиспам-фильтр: полный цикл ML

**Итоговое домашнее задание по дисциплине «Применение ML в кибербезопасности»**

Модель машинного обучения с NLP распознаёт спам в письмах и определяет категорию
письма (реклама, предложение работы, знакомства, финансы, доставка, безопасность).
Полный цикл: сбор и обработка данных → обучение → упаковка в микросервис → запуск.

## Результаты

| Метрика | Значение |
|---|---|
| Кросс-валидация (9 055 писем, 5 фолдов) | **F1 = 0.977**, precision 0.980, recall 0.975 |
| Ложные срабатывания на кросс-валидации | 0.68 % (46 из 6 748 нормальных писем) |
| Тестовый набор из задания (1 545 писем) | **F1 = 0.941**, precision **0.989**, 10 ложных срабатываний из 590 |
| Тест без писем, встречавшихся в обучении (342) | F1 = 0.802, precision 0.949 |
| Кросс-корпусная проверка SpamAssassin → Ling-Spam | F1 = 0.842 |
| Категория письма (6 классов + «прочее») | macro-F1 = 0.723 |

## Данные

Три источника (требование задания — несколько датасетов):

| Источник | Объём | Что даёт |
|---|---|---|
| SpamAssassin public corpus | 6 155 писем | сырой текст писем, разметка ham/spam, включая «сложные» нормальные письма |
| Ling-Spam | 2 875 писем | другой домен (рассылка), проверка переносимости |
| SpamBase (UCI) | 4 601 письмо | 57 табличных признаков (частоты слов и символов) |
| Транзакционные письма (синтетика) | 25 писем | сброс пароля, квитанции, коды — главный источник ложных срабатываний |

Итого **9 055 обучающих писем** (25 % спама) и **1 545 тестовых**.

Обработка: разбор MIME, извлечение текста из HTML, нормализация, замена URL и чисел
токенами, дедупликация (удалено 3 217 дубликатов между архивами корпуса),
проверка пересечения с тестовым набором.

## Модель

```
письмо → TF-IDF слова (1–2-граммы, 60 000) ─┐
       → TF-IDF символы (3–4-граммы, 200 000) ├→ 4 базовые модели → стекинг → порог
       → 94 числовых признака ────────────────┘
```

* **Базовые модели:** логистическая регрессия, линейный SVM (калиброванный),
  Complement Naive Bayes, градиентный бустинг (HistGradientBoosting).
* **Стекинг:** логистическая регрессия на логитах четырёх моделей и 94 числовых
  признаках; порог выбирается по OOF-предсказаниям.
* **Приоритет — precision:** порог 0.80 даёт precision 0.989 при 10 ложных
  срабатываниях из 590 нормальных писем (задача требует минимизировать FP).
* Все случайные генераторы зафиксированы (`SEED = 42`).

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt

# 1. Скачать корпуса и собрать данные
bash scripts/download_data.sh
.venv/bin/python src/load_data.py --raw data/raw --out data/processed/train.csv

# 2. Обучить модель (кросс-валидация, тест, метрики в artifacts/metrics.json)
.venv/bin/python src/train.py

# 3. Обучить модель категорий
.venv/bin/python src/category.py

# 4. Запустить сервис
.venv/bin/uvicorn service.app:app --host 0.0.0.0 --port 8000

# 5. Или в Docker
docker build -t antispam-service:1.0.0 -f service/Dockerfile .
docker run -p 8000:8000 -e SPAM_THRESHOLD=0.80 antispam-service:1.0.0
```

## Ограничения

* **Тестовый набор пересекается с обучающими корпусами:** 1 203 из 1 545 писем —
  точные копии писем SpamAssassin. Поэтому приводятся две оценки: на всём тесте
  (F1 = 0.941) и только на не встречавшихся письмах (F1 = 0.802, 342 письма).
* **Главный источник ложных срабатываний — транзакционные письма** (сброс пароля,
  подтверждение адреса, квитанции): они лексически похожи на фишинг. На невиданных
  нормальных письмах этого типа доля ложных срабатываний остаётся высокой (12 из 24),
  несмотря на добавление 25 синтетических примеров.
* **Язык:** корпуса англоязычные, в тесте есть русские письма; модель работает
  хуже на русском тексте, что подтверждается разбором ошибок.
* **Категории размечены слабо** (правилами по ключевым словам), поэтому macro-F1
  характеризует воспроизведение правил, а не экспертную разметку.

## Оценка существующих решений

| Решение | Подход | Результат |
|---|---|---|
| SpamAssassin | правила + байесовский классификатор | precision 0.99 на easy_ham, но требует ручной поддержки правил |
| SpamBayes | naive Bayes на токенах | F1 ≈ 0.95–0.97 на публичных корпусах |
| BERT-подобные модели | трансформеры | F1 0.98–0.99 на Enron/SpamAssassin, но на порядок дороже в инференсе |
| Коммерческие фильтры (Gmail, Яндекс) | ансамбли + репутация отправителя | precision > 0.999, недостижимо без инфраструктуры репутации |

Вывод: для текстов с ограниченным объёмом данных TF-IDF + линейные модели и
стекинг дают качество, близкое к трансформерам, при кратно меньшей стоимости.
