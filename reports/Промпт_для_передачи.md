## РОЛЬ

Ты — инженер ML и помощник студента. Нужно довести до сдачи итоговое домашнее
задание по дисциплине «Применение ML в кибербезопасности»: антиспам-фильтр на NLP

## ЧТО ТРЕБУЕТ ЗАДАНИЕ

**Тема:** разработать модель ML с использованием методов NLP, которая распознаёт
спам; дополнительно (для максимального балла) — модель категории письма
(реклама, предложение работы, знакомства и т. д.).

**Этапы:**

| Этап | Требование | Результат |
|---|---|---|
| 0 | анализ существующих решений ML в кибербезопасности | обзор в презентации |
| 1 | сбор и обработка данных; **несколько датасетов** — существенный фактор оценки (подсказка: SpamAssassin, LingSpam, SpamBase) | готовый набор данных |
| 2 | обучение модели, **минимизировать false positives**, метрики F1/Recall/Precision, кросс-валидация; протестировать на наборе из задания | обученная модель + код |
| 3 | упаковка в микросервис **Docker + FastAPI/Flask** | микросервис |
| 4 | **публикация** на публичном хостинге, доступном для демо | работающий URL |
| 5 | одна презентация на команду по шаблону (копия шаблона) | заполненная презентация |
| 6 | каждый участник отправляет ссылку; доступ открыт; имя файла содержит ФИО, группу и «Итоговое задание» | ссылка в задании |

**Форма сдачи:** ссылка на облачную презентацию (в тексте задания встречаются и
«Яндекс презентация», и «Google презентация» — PPTX подходит для обеих).
Дедлайн — по LMS. Максимум 10 баллов; зачёт от 5.

**Про использование ИИ (из задания):** разрешено, если это не противоречит условиям,
студент осмысленно обрабатывает результат и сам делает выводы. Поэтому: все числа
должны быть проверяемыми, а студент — уметь объяснить любое из них.

## ОГРАНИЧЕНИЯ СРЕДЫ (проверено на практике, не повторять ошибок)

1. **Постоянного анонимного хостинга не существует.** Туннели (`trycloudflare`,
   localhost.run, serveo) живут, пока запущен процесс; serveo требует SSH-ключ.
   Минимум для постоянного хостинга — бесплатный аккаунт (Render через GitHub).
2. **Загрузка на GitHub в этой сети обрывается на файлах > ~12 МБ.** Поэтому
   модель разрезана на части по 7.8 МБ и загружена в Releases; git-история
   пересобрана, чтобы не тащить большие блобы (иначе push падает вечно).
3. **joblib-модель ломается при несовпадении версий sklearn** — версии закреплены
   в `service/requirements.txt` (numpy 2.5.4, pandas 3.0.6, scikit-learn 1.9.1,
   scipy 1.18.1, joblib 1.6.0, fastapi 0.143.3, uvicorn 0.54.0, Python 3.14.8).
4. **Класс `BaseModels` из `train.py`**: если обучать запуском `python src/train.py`,
   pickle ссылается на `__main__.BaseModels` и не грузится из сервиса. Исправлено
   `tools/fix_bundle.py`; при переобучении запускать через `python -m src.train`
   или повторно прогонять фиксер.
5. **Docker в этой среде:** нужен `DOCKER_CONFIG=/tmp/dcfg` (каталог `~/.docker`
   недоступен), `DOCKER_BUILDKIT=0`; colima не пишет конфиг — использовать Docker Desktop.
6. **Файловая песочница:** `~/Downloads` недоступен для записи, `/tmp` доступен,
   но очищается между днями; LibreOffice/PowerPoint нет, поэтому PPTX проверять
   программно (python-pptx) — считать переполнение текста и границы картинок.
7. **Личные абсолютные пути** (`/Users/andrey/...`) в коде не оставлять: в
   `run_all.sh` и скриптах используются относительные пути и переменные окружения.

## ПРАВИЛА РАБОТЫ (важные)

* Не выдумывать числа: все метрики брать из `artifacts/metrics.json` и
  `artifacts/category_metrics.json`.
* Всегда приводить **обе оценки** (на всём тесте и на 342 невиданных письмах) —
  это честность и сильная сторона работы.
* Ограничения модели не скрывать: транзакционные письма (сброс пароля, квитанции)
  дают ложные срабатывания; модель хуже работает на русском тексте, потому что
  корпуса англоязычные; категории размечены слабо.
* Репозиторий держать лёгким: модели в Releases, в git только код.
* Перед выводами проверять факты командами (`curl`, `docker ps`, чтение json),
  а не по памяти.

```bash
cd /Users/andrey/Documents/DeepSeek/Итоговое_задание_антиспам

# полное воспроизведение с нуля (~30 минут)

```
